## 1. 개요

와플파이가 공간을 돌아다니며 **본 물체의 이미지 특징(CLIP 임베딩)과 지도상 위치·관측 시각을 기억**한다. 사용자가 영어 문장(텍스트 또는 음성)으로 물체를 묘사하면, 텍스트-이미지 유사도로 기억 중 가장 그럴듯한 물체를 찾아 해당 위치로 자율 주행한다.

- **창의성**: 정해진 클래스가 아닌 자유로운 묘사("a red tumbler", "a black charger next to the laptop")로 검색 (open-vocabulary)
- **멀티모달**: 이미지 + 깊이 + LiDAR + 텍스트 (+ 음성)
- **완성도**: 지도 작성·위치 추정·주행은 검증된 부품(slam_toolbox, Nav2)을 쓰고, 핵심 기여는 "확률적 물체 기억 + 검색" 모듈에 집중

## 2. 동기

- 물건을 어디 뒀는지 잊는 일상 문제를 로봇의 공간 기억으로 해결
- 기존 객체 검출(detectNet, YOLO)은 학습된 클래스만 인식 → 실제 생활 속 물체 묘사를 다루기 어려움
- 수업에서 배우는 확률적 로보틱스(베이즈 업데이트, Kalman Filter, Occupancy Grid, 위치 추정)를 "물체 기억"으로 확장

## 3. 시스템 구성

### 기본: 원격 처리 (Jetson은 로봇 밖, Wi-Fi ROS 2)

```
[와플파이 (Raspberry Pi)]                          [Jetson Xavier NX (원격)]
 LiDAR ──────────────┐                            ┌─ SLAM(slam_toolbox) / AMCL / Nav2
 오도메트리 ──────────┤                            ├─ 물체 검출 (detectNet / YOLO, TensorRT)
 C920 (압축 영상) ────┼── ROS 2 (실습실 Wi-Fi) ──▶ ├─ 물체 거리: RealSense 깊이 → (없으면) LiDAR
 RealSense (깊이) ────┘                            ├─ CLIP 임베딩 추출 (FP16)
 모터 제어 ◀──────────────────────────────────── ├─ 확률적 물체 기억 DB
                                                   ├─ 질의: 영어 텍스트 (+ Whisper 음성)
                                                   └─ 대시보드 (WebRTC) → 노트북 브라우저
```

- 영상은 와플파이에서 **압축(JPEG) + 낮은 해상도·FPS**로 보낸다. 깊이는 컬러에 정렬(aligned)된 저해상도 영상으로 보낸다
- Wi-Fi 대역폭·지연 때문에 검출/깊이 FPS가 부족하면 → **탑재 모드**로 전환

### 대안: 탑재 모드 (원격 실패 시)

- Jetson을 와플파이 위에 고정하고 카메라를 Jetson USB 3.2 포트에 직접 연결 → 영상 전송이 필요 없음
- 전원: PE1000N 입력은 **12~24 VDC**이고, 와플파이 배터리는 11.1 V(3S LiPo)라서 **승압(DC-DC) 컨버터** 또는 **Jetson 전용 배터리**가 필요
- 배터리로 돌릴 때는 `nvpmodel` 저전력 모드를 쓰고, 주행 시간을 측정해서 데모 시간을 확보

### 모듈별 역할

| 모듈 | 입력 | 출력 | 사용 기술 |
|------|------|------|-----------|
| 지도 작성 / 위치 추정 | LiDAR, 오도메트리 | Occupancy Grid 지도, 로봇 pose | slam_toolbox, Particle Filter (AMCL) |
| 물체 검출 | C920 / RealSense 컬러 영상 | 물체 bounding box | detectNet(SSD-Mobilenet-v2) vs YOLO (TensorRT) |
| 물체 거리·위치 | bbox, 깊이(또는 LiDAR), 로봇 pose | 지도 좌표 물체 위치 + 공분산 | 깊이 역투영, 카메라→base_link→map 좌표 변환 |
| 물체 기억 | 물체 crop, 위치, 시각 | 기억 DB | CLIP 임베딩, 베이즈 업데이트, Kalman Filter |
| 질의 | 영어 텍스트 (음성) | 텍스트 임베딩 | CLIP 텍스트 인코더, (Whisper) |
| 검색 / 이동 | 질의 임베딩 | 목표 위치 → 주행 | 유사도 × 존재 신뢰도, Nav2 |

## 4. 핵심 아이디어: 확률적 물체 기억

물체(기억) 하나마다 저장하는 것:

- 위치 평균 `μ = (x, y)` 와 공분산 `Σ` (불확실성)
- CLIP 이미지 임베딩 `e`
- 마지막 관측 시각 `t_last`
- 존재 신뢰도 `p` (그 자리에 아직 있을 확률)

### 4.1 물체 위치 계산 (카메라 → 지도)

1. bbox 중심 부근 깊이의 **중앙값** `d` → 카메라 좌표 3D 점 `P_c = d · K⁻¹ [u, v, 1]ᵀ`
2. 동차 좌표 변환: `P_map = T_map←base · T_base←cam · P_c` (`T_map←base`는 AMCL pose, `T_base←cam`은 캘리브레이션 값)
3. RealSense가 없을 때 (C920만 사용)
   - 2D LiDAR는 바닥에서 약 20 cm 높이의 **수평면 한 장**만 스캔 → 책상 위 물체까지의 거리는 잴 수 없음 (같은 방향의 책상 다리·벽 거리가 잡힘)
   - 대안 ① **관측 자세 저장**: 물체를 본 로봇 자세 `(x, y, θ)`와 물체 방위각을 저장 → 질의 시 그 자세로 이동해 같은 방향을 보고 재확인 (거리 불필요)
   - 대안 ② **시선 삼각측량 + EKF**: 카메라를 방향만 아는 센서(bearing-only, L05)로 보고, 서로 다른 위치에서 본 시선의 교점으로 물체 위치 추정, 관측이 쌓이면 EKF로 갱신
   - LiDAR 거리(bbox 방위각의 스캔 값)는 **바닥에 놓인 물체**에만 사용

### 4.2 위치 융합: Kalman Filter

같은 물체를 다시 보면 관측 `z`(공분산 `R`, 거리가 멀수록 크게)로 위치를 갱신한다 (정지 물체 모델).

```
K = Σ (Σ + R)⁻¹
μ ← μ + K (z − μ)
Σ ← (I − K) Σ
```

- 같은 물체 판정: 위치 거리(마할라노비스) 임계값 + CLIP 임베딩 코사인 유사도 임계값을 둘 다 만족

### 4.3 존재 신뢰도: 베이즈 업데이트 + 시간 감쇠

검출기 특성: 검출률 `P(검출 | 있음) = d`, 오검출률 `P(검출 | 없음) = f`

- 그 자리를 봤고 **검출됨**: `p ← d·p / (d·p + f·(1−p))`
- 그 자리를 봤는데 **검출 안 됨** (물건이 옮겨짐): `p ← (1−d)·p / ((1−d)·p + (1−f)·(1−p))`
- **시간 감쇠** (오래된 기억일수록 불확실): `p ← 0.5 + (p − 0.5)·exp(−Δt / τ)` (`τ`는 실험으로 정함)
- "봤다"의 판정: 물체 위치가 카메라 시야(FOV)와 깊이 범위 안에 있고 가려지지 않았을 때만 갱신

### 4.4 검색 점수

```
s_i  = cos(CLIP_text(q), e_i)                    # 질의-기억 유사도
w_i  = softmax(s_i / T)                          # 후보끼리 정규화 (T: temperature)
score_i = w_i × p_i                              # × 존재 신뢰도
```

- 점수 상위 후보(Top-3)를 순서대로 방문 → 도착 후 **현재 화면 재확인**(검출 상자 + CLIP 창 검색, 배경 문장과 softmax 경쟁)
- 재확인 확률 ≥ 0.5 → 찾음 / < 0.5 → 신뢰도 하락 후 다음 후보

## 5. 수업 내용과의 연결

| 수업 주제 | 프로젝트 적용 |
|-----------|---------------|
| Linear Algebra, Homogeneous Coordinates | 카메라 → 로봇 → 지도 좌표 변환 (4.1) |

| Kalman Filter / EKF | 물체 위치 추정 (반복 관측 융합, 4.2) |
| Particle Filter, SLAM | 지도 작성(slam_toolbox) 및 로봇 위치 추정(AMCL) |

| 장소 | 작업 |
|------|------|
| 집 (노트북) | 코드 개발, Gazebo 시뮬레이션, CLIP·Whisper 노트북 검증, 녹화한 rosbag 재생으로 오프라인 테스트 |
| 실습실 | pull한 코드 실행·검증, rosbag 녹화(컬러·깊이 포함), Jetson 성능 측정(FPS·메모리), 데모 리허설 |

**실습실 시간을 아끼기 위한 규칙**
- 실습실에서 코드 수정 최소화 → 문제가 생기면 로그·rosbag만 챙겨 와서 집에서 수정
- 검증은 스크립트 한 번으로 실행되게 준비 (예: `scripts/verify_stage1.sh`)
- 방문 전 체크리스트 작성: 이번 방문에서 확인할 항목, 녹화할 데이터
- 지도 작성, 센서 캘리브레이션, TensorRT 엔진 빌드는 Jetson·로봇에서만 가능 → 결과 파일(지도, 캘리브레이션 값, 엔진)을 저장해 두기

**집과 Jetson 환경 차이 주의**
- 노트북(x86)과 Jetson(ARM64 + JetPack)은 패키지 버전·설치 방식이 다름 → 버전 고정, conda 환경 파일로 관리
- TensorRT 엔진은 Jetson에서 직접 빌드 (노트북 엔진 사용 불가)
- 무거운 변환(ONNX export 등)은 CPU에서 하거나 다른 프로그램을 끄고 실행
- 대용량 파일(모델 가중치, rosbag)은 Git 제외, 구글 드라이브로 공유

## 10. 위험 요소 및 대응

| 위험 | 대응 |
|------|------|
| ROS 2 배포판 불일치 (와플파이 ↔ Jetson) | 첫 방문에서 `printenv ROS_DISTRO` 확인 후 통일 방법 결정 (필요 시 Jetson에서 Docker) |
| 원격 모드에서 Wi-Fi 대역폭·지연 (컬러+깊이 전송) | 압축 영상, 해상도·FPS 축소, 필요한 프레임만 전송 → 부족하면 탑재 모드 |
| 탑재 모드 전원 (12 V 미만 배터리) | 승압 컨버터 또는 Jetson 전용 배터리, 저전력 `nvpmodel` 모드, 주행 시간 측정 |
| Jetson 8 GB 메모리 부족 (SLAM + Nav2 + 검출 + CLIP + Whisper) | TensorRT/FP16, CLIP은 검출 시에만, Whisper는 질의 시에만 로드 |
| RealSense를 못 쓰는 경우 | 관측 자세 저장 후 재방문·재확인, 시선 삼각측량 + EKF, 바닥 물체만 LiDAR 거리 |
| 카메라-로봇 캘리브레이션 오차 | 초기에 캘리브레이션 시간 확보, Kalman 융합으로 반복 관측 평균 |
| CLIP 창 검색이 작은 물체에서 불안정할 수 있음 | 후보 위치로 가까이 이동 후 재확인, 작은 창 추가, (확장) NanoOWL |
| 검출기 오검출·미검출 | detectNet vs YOLO 비교 후 선택, CLIP 재확인 단계로 보완 |
| 음성 인식 부정확 | 영어 질의 + Whisper, 부정확하면 텍스트 입력 |
| 자율 주행 불안정 | 텔레옵 순찰로 기억 단계 대체 |
| 실습실 Wi-Fi에서만 접속 가능 | 집에서 개발·push, 실습실은 검증만, 시뮬레이션·rosbag 활용 |
